# SYS API drift closure tail

The generated `api/sys.json` public inventories and schema edges match the frozen `api/sys.json` fixture copied into `orna-conformance-v1/tests/fixtures/reference/`, after normalizing the `source_of_truth` provenance string. That one string differs intentionally: the generated artifact names the local `#[ornasys]` methods as its input, while the frozen artifact names the normative source chapters. `sys_api_drift_closure_tail.rs` pins this relationship.

The reference declares both a human-readable relation `key` and structured `key_fields`, but does not prescribe how their text must be kept synchronized. In this repository, `key` is the `key_fields` paths joined with ` + `. Generation and semantic API loading now reject either representation drifting from the other. This covers valid alternate paths too: a mutation that changes both values still fails the frozen-schema comparison.

The publication source requires effective policy and pending/published state to be visible through `sys.Storage` and runtime maintenance metadata, but it does not specify typed `published_rows` or `published_bytes` fields on `sys.Storage` or `sys.MaintenanceJob`. The frozen API exposes `publication_policy: sys.Value`, pending counters, and `last_publication`; the runtime ledger also carries counters that are not declared public fields. This slice follows the frozen type surface and does not promote those internal counters or add a typed `sys.PublicationPolicy`. Checked-in `.orna` fixtures prove the published fields type-check and the extra runtime fields remain unavailable to portable source.

The final generator-side signature checks now resolve defaults through closed enum variants or singleton value fields, reject defaults whose resolved type differs from the parameter type, and require parameters without defaults to precede defaulted parameters. The semantic API loader already applies the same rules; focused mutation tests pin both sides. The reference lists the current signatures but does not separately define that signature-validation algorithm, so this slice documents the existing loader behavior as the pragmatic rule. A crate-local `.orna` fixture proves ordinary calls use enum, singleton, boolean, and optional defaults through the published API.
